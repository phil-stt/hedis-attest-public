# Attest synthetic data

Everything in this directory is synthetic. Names come from small generic name lists, providers and clinics are invented, and every clinical detail comes from a template in `scripts/generate_data.py`. No real member, provider, or claims data appears here.

Regenerate with `python3 scripts/generate_data.py` (seeded, deterministic; overwrites this directory except this README).

## Files

| File | Contents |
|---|---|
| `members.json` | 56 synthetic members: `member_id` (`SYN-…`), name, sex, DOB, age at end of MY2026, attributed PCP |
| `providers.json` | 6 invented providers across 3 invented clinics |
| `gaps.json` | 68 open gaps (CBP, GSD, COL-E): member, measure, provider, due date, `document_ids` in date order. 8 gaps have no documents yet (chase targets). |
| `documents.json` + `documents/*.txt` | 61 documents across 48 charts: progress notes, faxed lab reports, an ED note, a discharge summary, procedure notes |
| `splits.json` | 70/30 member-level split (34 dev / 14 held-out members), stratified by measure and scenario category |
| `labels/dev.json` | Expected findings for the 42 dev gaps. Use these for prompt work. |
| `labels/heldout.json` | Expected findings for the 18 held-out gaps. **The eval runs on these. Nobody tunes against them.** |
| `labels/heldout_review.md` | Human-readable sheet for checking the held-out labels by hand |

## Label conventions

- `expected_finding`: `numerator` (evidence closes the gap), `exclusion` (evidence removes the member from the denominator), `abstain` (something that looks like evidence but cannot be used, with a reason), `none` (no evidence that closes the gap; includes a valid but uncontrolled BP and a declined screening).
- `abstain_reason`: `bp_range_or_threshold`, `ineligible_setting` (ED, inpatient, day of procedure), `home_reading_not_digital`, `missing_value`, `missing_or_ambiguous_date`, `outside_lookback_window`, `not_completed` (ordered, kit handed out, or result pending).
- `expected_fields`, by measure:
  - CBP: `systolic`, `diastolic`, `reading_date`, `setting` (`outpatient` | `home`), `source` (`office` | `digital_home_device`)
  - GSD: `a1c_value`, `test_date` (the tier is derived from the value: <8.0 controlled, >9.0 poor)
  - COL-E: `procedure_type` (`colonoscopy` | `fit` | `fit_dna` | `flexible_sigmoidoscopy` | `ct_colonography`), `procedure_date`
  - Exclusions: `exclusion_type` (`hospice` | `palliative_care` | `advanced_illness_frailty` | `total_colectomy` | `colorectal_cancer` | `esrd_dialysis`), `supporting_date`
- Dates are ISO and carry only the precision the document gives: `2026-06-02`, `2024-09`, or `2019`.
- `evidence`: the passage a reviewer should see highlighted, as `doc_id` plus character offsets `start`/`end` into the document text.
- Most recent reading in the measurement year governs. On a same-day repeat, the lowest systolic and lowest diastolic govern.

## v2 population (`data/v2/`)

Generated by `scripts/generate_data_v2.py`, which reuses the v1 scenario library and adds the layer the demo lacked. Still entirely synthetic.

- **Tranches**: a two-level hierarchy. Parents are four invented lines of business (Individual MA, Group MA, D-SNP, Medicaid) plus a Military plan line that exists with members but no gaps: the gap engine excludes it (not rated under Stars or HEDIS), and the exclusion is shown on the Insights page. Children are eight provider-group tranches (line of business × group type: owned primary care, large IPA, independent practices, out-of-network); `gaps.tranche_id` and `members.tranche_id` name the provider group, the unit that owns closing the gap. Region is a member attribute (`members.region`), used as a filter, not a tranche.
- **Sources** follow the provider group, which is where evidence differs: owned groups have an EHR feed (one per tranche); large IPAs an EHR feed plus the regional HIE; independent practices send faxes and appear in the HIE; out-of-network care arrives through the HIE and fax. The first source is the tranche's primary. Every non-EHR document refers to the member by that source's own identifier (`HIE-…`, `FAX-…`), joined by the `member_identity` table; the plan id never appears on such a page. For an independent practice even primary documents carry a FAX reference.
- **Fragmentation**, tagged per labeled gap: `evidence_in_secondary_source` (the document that closes the gap exists only in the HIE or fax source), `duplicate_document` (the note resent from another source with a routing header and whitespace drift), `cross_provider` (the note's author is not the attributed PCP). Some gaps have no chart in any source.
- **Eval block** (`eval-block.jsonl.gz`, committed, 288 gaps): one held-out and two dev charts per (provider-group tranche, measure, category), generated first and identically regardless of population size. Labels: `labels/v2-heldout.json` (96), `labels/v2-dev.json` (192), review sheet `labels/v2-heldout_review.md` grouped by tranche. The held-out labels are hand-reviewed before the first v2 run; nobody tunes against them. Label rows add `tranche_id`, `evidence_source` (`primary` | `secondary` | `none`, relative to the tranche's primary source), and `fragmentation`.
- **Population** (`population-<N>.jsonl.gz`, gitignored): the eval block plus unlabeled bulk gaps up to N, with pairing and chase-only gaps per unit. `make data-v2 GAPS=100000` regenerates it in a few minutes (3.5 on a laptop; 11.5 MB gzipped); import with `python -m attest.seed import-data --bundle data/v2/population-100000.jsonl.gz`.

Bundle format: gzipped JSONL, one `{"t": <table>, "r": <row>}` per line, table-major (tranches, providers, members, identities, gaps, documents, gap_documents). Gap ids are `G2-nnnnnn`, member ids `SYN-2nnnnnn`, so v1 and v2 never collide.
